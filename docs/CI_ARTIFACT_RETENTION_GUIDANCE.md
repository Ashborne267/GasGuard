# CI Artifact Retention Guidance

This document defines the storage lifecycle, security considerations, and retention policies for all build, scan, test, and release artifacts generated by GasGuard CI/CD pipelines.

## Retention Policy Matrix

Every workflow that generates or uploads artifacts must declare an explicit retention duration. GasGuard categorizes CI artifacts into four tiers:

| Tier | Pipeline Type | Retention Window | Recommended | GitHub Actions Syntax | GitLab CI Syntax |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **PR & Ephemeral** | Pull requests, merge queues, unit test runs | 1 – 14 days | 7 days | `retention-days: 7` | `expire_in: 7 days` |
| **Scheduled Scans** | Nightly scans, dependency checks, cron analysis | 7 – 30 days | 30 days | `retention-days: 30` | `expire_in: 30 days` |
| **Release Artifacts** | Release builds, SBOMs, Sigstore bundles, provenance | 30 – 90 days | 90 days | `retention-days: 90` | `expire_in: 90 days` |
| **Compliance Archives** | Audit logs, annual compliance reports | 90 – 365 days | 180 days | External S3 / Glacier | External package registry |

## Configuration Guidelines

### 1. GitHub Actions

Do not rely on repository default retention settings (which often default to 90 days for all ephemeral jobs, incurring unnecessary storage costs). Always declare `retention-days` on `actions/upload-artifact@v4`:

```yaml
- name: Upload Scan Results
  uses: actions/upload-artifact@v4
  if: always()
  with:
    name: gasguard-scan-report
    path: gasguard-report.json
    retention-days: 30
```

For PR and ephemeral validation runs:

```yaml
- name: Upload Test Coverage
  uses: actions/upload-artifact@v4
  with:
    name: coverage-report
    path: coverage/
    retention-days: 7
```

For release workflows (enforced by test suite `packages/cli/src/release-artifact-policy.spec.ts`):

```yaml
- name: Upload Release SBOM
  uses: actions/upload-artifact@v4
  with:
    name: sbom-spdx
    path: sbom.spdx.json
    retention-days: 90
```

### 2. GitLab CI

In `.gitlab-ci.yml`, use the `artifacts:expire_in` directive:

```yaml
gasguard-scan:
  stage: test
  script:
    - gasguard scan . --format gitlab -o gl-code-quality-report.json
  artifacts:
    reports:
      codequality: gl-code-quality-report.json
    expire_in: 30 days
```

For merge request pipelines:

```yaml
unit-tests:
  stage: test
  script:
    - pnpm test
  artifacts:
    paths:
      - coverage/
    expire_in: 7 days
```

## Storage Optimization Best Practices

1. **Avoid Archiving Intermediate Build Directories**: Never upload `node_modules`, `target/`, or `.git` directories.
2. **Selective File Globs**: Restrict uploads strictly to the generated report or binary files:
   ```yaml
   path: |
     dist/*.tar.gz
     reports/*.json
   ```
3. **Compression**: For large log files, compress with `gzip` or `zstd` prior to upload.
4. **Conditional Uploads**: Use `if-no-files-found: ignore` or upload only when test/scan reports exist.

---

## Archival & Expiration Recovery

- **Ephemeral PR Artifacts**: If expired, re-trigger the workflow dispatch or push a commit to the PR branch.
- **Scheduled Scans**: Past trend data is maintained in GasGuard history tables; raw artifact JSON is retained for 30 days for debugging.
- **Published Release Assets**: Files attached to published GitHub Releases (binaries, SBOM, SHA256SUMS) are permanent and do not expire. Verify release asset integrity using:
  ```bash
  gh attestation verify ./gasguard-linux-x64 --repo MDTechLabs/GasGuard
  ```

---

## Automated Policy Enforcement

GasGuard enforces retention rules via automated tests:
- `src/ci/artifact-retention-validator.spec.ts`: Validates that every workflow file in `.github/workflows/` defines valid, bounded `retention-days`.
- `packages/cli/src/release-artifact-policy.spec.ts`: Enforces 90-day retention for all release workflow artifacts.
